## 项目目标和基本约束

Vicdata 是面向《维多利亚 3》的静态资料查询网站。当前公开主站使用 Victoria 3 1.13.9 数据，提供国家、地区、文化、公司、意识形态、经济和其他资料的浏览、筛选、搜索与地图查看。项目与 Paradox Interactive 没有从属、授权或合作关系。

数据应优先来自本地游戏文件和已有提取器。名称、分类、机制解释和界面词条不能凭空编造；遇到缺失或歧义时，先保留证据并在交接记录中写明待确认项。前端改动要同时考虑简体中文、英语、桌面宽度和窄屏宽度。静态检查通过后，涉及布局、点击、路由、滚动或数据加载的任务还要做有针对性的浏览器验证。

修改时保留无关的用户文件和临时文件。不要重置工作区，也不要覆盖其他模型尚未交接的改动。没有明确授权时，不要提交、推送、部署或删除文件。

## 多模型协作方式

模型之间通过仓库文件、Git 差异和交接记录共享上下文，不依赖复制聊天记录。建议使用以下分工：

- GPT：确认功能目标、信息架构、数据语义和取舍，负责最终整合。
- Claude：在 VS Code 中进行跨文件阅读、前端实现、脚本修改和仓库级调试。
- Gemini：整理大量外部资料或大批量文件，输出带路径和证据的研究记录。
- DeepSeek：处理格式转换、批量清洗、重复项检查和一次性数据脚本；结果必须由另一模型抽查。
- GPT 或 Claude：在合并前做独立代码审查和回归检查。

这只是工作角色，不代表某个模型只能做某类任务。小改动、同一文件的连续调试和需要共享大量上下文的任务保持单线程。只有在数据调查、前端检查、资料整理等方向彼此独立时才并行安排，避免多个模型同时修改同一文件。

## 任务交接规则

每个模型开始前先说明：目标、允许修改的路径、禁止触碰的范围、验证命令和是否允许提交。完成后在对应的工作记录或任务文件中写明：

```markdown
# 任务名称

## 状态
- 已完成：
- 未完成：
- 尚待确认：

## 修改文件
- `path/to/file`

## 验证
- 命令：
- 结果：

## 风险和后续
- 数据、兼容性、发布或浏览器验证方面的已知风险。
```

交接时必须区分“本地实现完成”“已提交并推送”“公开站点已发布”。浏览器截图、临时缓存、审计脚本和未纳入本轮范围的设计文件，不要在没有说明的情况下混入提交。

## 常用命令

本地启动主站：

```powershell
node scripts/serve_site.mjs site 8876
```

常用检查：

```powershell
node scripts/check_publish_bundle.mjs
node scripts/check_economy_board_contract.mjs
node scripts/check_multilingual_bundles.mjs --site-version site/versions/1.13.9
git diff --check
```

需求表相关检查：

```powershell
node scripts/check_pop_needs_database.mjs
node scripts/check_goods_needs_contract.mjs
node scripts/check_goods_needs_browser.mjs
```

原版内容提取与检查：

```powershell
node scripts/build_content_data.mjs
node scripts/check_content_extraction.mjs
```

浏览器检查应优先使用 `domcontentloaded` 加项目自身的就绪条件；不要因为静态资源持续加载而把 `networkidle` 当作唯一成功条件。验证主站、`site/vc/` 和独立 VC 站点时，先确认页面标题、入口路径和数据版本，避免把不同站点的结果混在一起。

## 继续工作时的默认做法

先检查工作区，再阅读当前任务的工作日志和计划；随后做低输出的静态检查，确认已有改动属于哪个任务。实现完成后运行对应的契约检查和最小范围浏览器回归，更新工作日志，最后报告本地、Git 和公开站点分别处于什么状态。没有新的明确任务时，不要自行扩大到其他板块，也不要把本地未提交功能发布出去。
