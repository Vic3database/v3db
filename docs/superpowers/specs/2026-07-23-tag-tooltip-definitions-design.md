# 标签悬停定义文件设计

## 目标

将可编辑的标签悬停文案从组件实现中移出，集中到 `site/app/tag-tooltip-definitions.js`。维护时只需新增或修改语义键对应的分类与说明，不需要进入标签生成器或悬停交互代码。

## 文件与数据边界

新文件只导出全局常量 `TAG_TOOLTIP_DEFINITIONS`。每个条目以稳定语义键为键，并包含 `category` 与 `description` 两个可选字段：`category` 显示在悬停框的分类行，`description` 显示在说明行。文件采用普通 JavaScript 对象字面量，允许中文注释与尾随逗号。

```js
const TAG_TOOLTIP_DEFINITIONS = {
  "country-status:start": {
    category: "国家状态",
    description: "该国家在1836年开局时已存在。",
  },
};
```

标签的可见名称、语义键与搜索词仍由当前数据和标签生成器提供，不在定义文件重复维护。定义文件不包含样式、事件处理、实体详情或搜索逻辑。

## 渲染与后备规则

页面在 `components.js` 之前加载定义文件。标签生成器按照“完整语义键、语义类别前缀、来源键、样式类别”的既有顺序查找条目，并将命中的 `category` 与 `description` 写入概念元数据。

悬停框优先显示定义文件的说明；未命中时，继续读取国家、文化、法律、意识形态等实体数据的中文说明；仍无说明时生成通用文字。标签名称、语义键、实体上下文和“右键搜索”提示保持现有显示规则。原生 `title` 仍在显示页面悬停前移除，因此不会出现浏览器小悬停。

## 验证

静态契约测试应确认定义文件被页面在正确顺序加载、组件不再内联定义表，并覆盖“开局”“殖民国家”“公国”三项的定义读取。现有悬停契约和浏览器检查继续确认说明行可见、未定义标签有后备文案、触发元素及子元素均无 `title`。
