# Victorian Century 日志、事件、决议板块设计

## 板块结构

Victorian Century 独立站在“游戏内容”导航中提供“日志”“事件”“决议”三个入口。三个板块均使用左侧筛选、中间列表、右侧详情的固定三栏布局，不套用地图板块布局。

日志路由为 `#/journal`，事件路由维持 `#/event`，决议路由为 `#/decision`。原有 `#/content/journal`、`#/content/event`、`#/content/decision` 路由分别重定向到三个新入口，避免旧链接失效。

## 日志板

左栏提供搜索、来源筛选、VC 变更筛选和日志组导航。中栏按日志组与日志 ID 排序，同一日志组连续显示；卡片显示标题、ID、日志组、来源标记和 VC 变更标签。右栏显示说明、显示条件、开启条件、完成条件、失败条件、完成与失败效果、触发事件、来源文件和原始脚本。

## 事件板

事件板沿用现有的搜索、事件类型、通用与风味事件、事件标签、事件组导航及三栏交互。Victorian Century 独立站加载以原版 1.13.10 为基线合并后的事件；原版 1.13.9 站继续加载原有事件数据。卡片和详情增加 VC 变更标签，现有标题、ID、分类、选项、修正效果与详情结构保持不变。

## 决议板

左栏提供搜索、来源筛选和决议分组导航。中栏按来源文件形成的稳定分组与决议 ID 排序，卡片显示标题、ID、分组和来源标记。右栏显示说明、显示条件、执行条件、执行效果、人工智能权重、触发事件、来源文件和原始脚本。当前需求不要求决议显示 VC 新增或调整标签。

## VC 变更判定

条目仅存在于模组数据时标记为“VC新增”。同一 ID 同时存在于原版与模组数据，并且定义脚本或本地化内容有差异时标记为“VC调整”。模组目录不包含同 ID 定义时，不根据文件名、日志组或引用关系推断调整状态。

版本基线需要先固定为原版 1.13.10，再与 Victorian Century 当前文件比较。当前本地原版为 `release/1.13.10`，提交版本为 `58c9ac0605f52c0fbdd353c1921db0ce08e7b026`。1.13.9 到 1.13.10 的原版差异为：日志数量仍为 419，决议数量仍为 60；事件从 2,261 条增加到 2,264 条，新增 `treaty_port_inheritance_events.1`、`.2`、`.3`；`algeria_events.8` 和 `society_tech_events.104` 的脚本发生变化；17 个事件的本地化发生变化。日志中的 `je_agricultural_development` 也在 1.13.10 相对 1.13.9 中发生脚本变化。

因此 VC 合并与 VC 标签必须以 1.13.10 为原版基线重新生成。标签比较的顺序是：先比较 1.13.10 原版和 VC 的定义，再单独记录 1.13.9 到 1.13.10 的原版更新，避免把 Paradox 的版本更新误标为 VC 调整。

## 数据与验证

独立站内容数据继续由 `database/victorian_century` 生成。构建阶段把合并事件转换成现有事件板需要的事件类别、通用或风味分类、多标签、事件组选项和修正效果格式，并将日志与决议写入独立数据块。验证覆盖数量、标签判定、路由兼容、三个板块的三栏布局、筛选、卡片选择和右栏详情。
