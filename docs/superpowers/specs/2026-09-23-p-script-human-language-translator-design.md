# P语言中文解读器设计

## 1. 目标与范围

Vic3 Database 为数据库中已有的日志、事件和决议源码提供构建时生成的中文解读。第一版不接收用户临时粘贴的任意脚本，也不在浏览器中调用大模型。所有结果由确定性规则生成，可以重复构建、自动测试和人工校正。

详情页提供三个页签：

1. 纯原始脚本：显示未经修改的 P 语言源码。
2. 注释交错：保留完整源码，在对应行或代码块旁显示中文注释、实体引用和证据标记。
3. 纯中文解读：隐藏大部分脚本语法，按脚本结构生成连贯中文。

第一版覆盖日志、事件和决议。日志按显示条件、启动效果、完成条件、完成效果、失败与超时处理、交互按钮组织；事件按触发条件、立即效果、选项组织；决议按显示条件、执行条件、执行效果组织。

## 2. 总体架构

构建管线为：

```text
原版脚本
→ 保真语法树
→ 作用域与引用分析
→ 官方本地化解析
→ 标准中文语义节点
→ 人工覆盖
→ 页面数据
→ 原始脚本／注释交错／纯中文解读
```

解释核心供日志、事件和决议共用，各对象类型只提供顶层结构词典。原始脚本继续使用现有 `raw` 或脚本字段；新增解释数据与原文分离，不能覆盖原始内容。

输出采用可序列化的语义数据，不在构建器中直接拼接最终 HTML。浏览器渲染器根据同一语义数据生成注释交错视图和纯中文视图，避免两套解释发生偏差。

## 3. 解析层

解析器必须保留：

- 原始行文本、缩进和换行；
- 源文件与一基行号；
- 花括号层级；
- 字段、标量值、无键列表项和重复字段；
- `=`、`?=`、比较运算符和作用域链；
- 行内及整行原始注释；
- 匿名块、类型前缀值块和带引号动态键。

解析器不得把重复字段合并为一个对象属性。P语言中的字段顺序、重复项和匿名块具有潜在语义，必须按原顺序保存。

语法树节点需要稳定标识。首选标识由对象类型、对象键、字段路径、同路径出现序号和源码内容摘要组成；行号仅用于显示和最后回退，不能作为人工覆盖的唯一键。

## 4. 语义层

每个语义节点至少包含：

```json
{
  "node_id": "journal:je_brazilian_nation_building/complete/1",
  "source": {
    "file": "common/journal_entries/02_brazilian_nation_building.txt",
    "line": 20
  },
  "raw": "has_technology_researched = nationalism",
  "text": "已研究“民族主义”科技",
  "scope": {
    "root_kind": "country",
    "current_kind": "country",
    "path": ["ROOT"]
  },
  "references": [
    {
      "kind": "technology",
      "key": "nationalism",
      "label": "民族主义",
      "href": "#/technology/nationalism"
    }
  ],
  "evidence": {
    "kind": "official-localization",
    "source_file": "localization/simp_chinese/technology_l_simp_chinese.yml"
  },
  "confidence": "confirmed"
}
```

解释顺序固定为：识别对象顶层结构，建立根作用域，沿代码块追踪当前作用域，解释字段与值，解析实体引用，合并官方简体中文本地化，最后应用人工覆盖。

## 5. 中文注释标准

注释交错视图保留完整源码。简单字段使用行旁注释；复杂代码块在开括号处说明职责，在闭括号处按需概括逻辑。复制注释版时生成合法的 P 语言 `#` 注释。

示例：

```paradox
immediate = { # 日志条目激活时立即执行
	cu:brazilian = {
		save_scope_as = brazilian_culture
	} # 将巴西文化保存为命名作用域 brazilian_culture
}
```

固定术语包括：根作用域、当前作用域、上一级作用域、命名作用域、临时命名作用域、当前作用域变量、全局变量、触发条件、脚本值、效果、对象链接。

逻辑块采用固定表达：

- 普通条件块中的同级条件表示全部成立；
- `OR` 表示至少一个分支成立；
- `NOR` 表示所有分支均不成立；
- `NOT` 表示内部整体不成立；
- `NAND` 表示内部条件不能全部同时成立；
- `if`、`else_if`、`else` 按书写顺序解释；
- `?=` 表示对象存在时进入该作用域检查；对象不存在时对外层条件的影响必须结合所在逻辑块说明；
- `any_scope_state` 表示存在至少一个符合条件的州；同一块含 `count` 时，说明计数对象是满足该块全部条件的州；
- `show_as_tooltip` 译为“只在提示中展示以下效果”，不能当作实际执行；
- `custom_tooltip` 译为“以指定本地化文本显示条件或效果”；
- `save_scope_as` 译为“保存持久命名作用域”；
- `save_temporary_scope_as` 译为“保存当前执行链中的临时命名作用域”；
- `set_variable` 译为“设置当前作用域变量”；
- `set_global_variable` 译为“设置全局变量”。

官方简体中文本地化优先于自行翻译。界面显示中文名称与内部键，不能丢弃内部键。缺少官方本地化时使用内部键或经过审核的人工覆盖，不能自动编造专名。

## 6. 内部键标记系统

作用域、变量、触发器、效果和实体引用使用结构化标记，不能只生成 Markdown 文本。标记统一保存原始键、类型、中文名称、当前作用域、目标对象、链接和证据。

标准类型包括：

| 类型 | 标准显示 | 行为 |
|---|---|---|
| 根作用域 | `ROOT · 根作用域` | 显示根对象类型 |
| 当前作用域 | `THIS · 当前作用域` | 显示作用域路径 |
| 上一级作用域 | `PREV · 上一级作用域` | 支持连续层级 |
| 命名作用域 | `scope:brazilian_culture · 命名作用域` | 与变量区分 |
| 当前作用域变量 | `nordestinos_integrated · 国家变量` | 类型由当前作用域推导 |
| 全局变量 | `global_var:china_shatters · 全局变量` | 固定全局标记 |
| 国家引用 | `BRZ · 巴西` | 跳转国家详情 |
| 文化引用 | `brazilian · 巴西文化` | 跳转文化详情 |
| 科技引用 | `nationalism · 民族主义` | 跳转科技详情 |
| 州区引用 | `STATE_BOMBAY · 孟买` | 跳转州区详情 |
| 法律引用 | `law_slavery_banned · 废除奴隶制` | 跳转法律详情 |
| 脚本触发器 | `has_variable · 拥有变量` | 跳转 P语言语法说明 |
| 脚本效果 | `save_scope_as · 保存命名作用域` | 跳转 P语言语法说明 |
| 未识别键 | 原始键＋未识别标记 | 不生成虚构译名 |

普通变量的对象类型随当前作用域变化。无法确认当前对象类型时，显示“当前作用域变量”，并附静态推断或运行未确认标记。

实体引用复用现有 `conceptPill` 和详情路由。第一版至少支持国家、文化、科技、州区、法律、商品、公司、建筑、宗教、意识形态、事件、日志和决议。实体不存在或目标板块未提供详情页时，保留不可点击标记。

## 7. 证据模型

证据标记与注释文字分离，渲染为独立徽标。标记类型为：

- 官方说明：来自原版专用说明文件；
- 官方本地化：来自原版简体中文本地化；
- 原版用例：来自原版定义或代表性调用；
- 静态推断：由作用域和结构分析得出，但没有专用说明；
- 运行未确认：静态文件无法证明刷新、时序、默认值或引擎行为。

徽标不写入代码注释，不混入 Markdown 正文。点击徽标显示依据类型、文件、行号和简短说明。复制注释版时不复制徽标；导出 Markdown 时证据写入独立元数据区。

## 8. 三个页签

### 8.1 纯原始脚本

显示未经修改的源码，保持原始缩进、注释和换行。支持复制，不插入实体链接或证据标记。

### 8.2 注释交错

不能使用单一 `<pre>`。每个源码行渲染为独立行，包含代码、中文注释、实体标记和证据徽标。源码与注释视觉上分栏或分层，窄屏时上下排列。复制功能提供“复制原文”和“复制带 P语言注释脚本”两个动作。

### 8.3 纯中文解读

按对象类型的固定语义区块生成连贯中文。实体名称可点击，证据徽标位于相关句段旁。无法可靠解释的内容放入“原始条件”或“原始效果”，保留格式化源码和未解析标记。

## 9. 人工覆盖

人工覆盖使用独立的版本化文件，不修改原始脚本、语法树或自动生成结果。覆盖键由对象类型、对象键、稳定节点标识组成，可以：

- 修改中文注释；
- 指定或清除实体引用；
- 补充作用域说明；
- 调整证据类型；
- 标记运行语义未确认；
- 合并或拆分纯中文解读段落。

原版更新后先用稳定字段路径和内容摘要重新匹配。未能匹配的覆盖项写入构建报告并使契约检查失败，不能静默丢弃。

## 10. 构建报告与错误处理

每次构建输出：对象数、源码行数、已解释行、部分解释行、未解释行、实体引用数、无效实体引用、人工覆盖数、失效覆盖数、各证据类型数量。

解析失败时保留原始脚本，页面仍可显示纯原文。单个节点解释失败不能阻止其他节点生成；结构级解析错误、失效覆盖和指向不存在对象的强制引用必须使检查失败。

解释器不能把无法确认的内容写成确定事实。默认值、执行顺序、随机抽取、作用域生命周期、修正传播和界面刷新只有在官方说明或运行证据支持时才能明确陈述。

## 11. 第一版验收

第一版以 `je_brazilian_nation_building` 为完整样例，并覆盖一个事件和一个决议作为跨对象验证。必须满足：

1. 日志、事件、决议详情页均有三个页签；
2. 原始脚本逐字保持；
3. 注释交错视图正确区分变量与命名作用域；
4. `show_as_tooltip` 不被解释成实际效果；
5. 官方简体中文本地化用于标题、条件和实体名；
6. 民族主义科技等实体可跳转到现有详情页；
7. 证据使用独立徽标；
8. 纯中文解读由同一语义数据生成；
9. 人工覆盖能够稳定重建，失效覆盖会被报告；
10. 浏览器契约验证三个页签、实体跳转、证据徽标、复制功能和移动端布局。

第一版不承诺覆盖所有 P语言命令。未识别语法必须保留原文并明确标记，不能阻塞纯原始脚本展示。
