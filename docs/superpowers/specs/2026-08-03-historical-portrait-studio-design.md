# 历史角色肖像展柜设计

## 目标与范围

为 Victoria 3 资料库建立一条离线肖像生产流程。流程从原作角色模板取得已定义的 DNA、文化和身份数据，在本机游戏中以同一背景、机位、光照与待机姿态显示角色，再将画面截为统一规格的二维半身像。网站只保存和读取静态 WebP 或 PNG 图像及其索引，不在服务器或浏览器中运行人物建模。

首轮只处理八名角色：维多利亚女王、拿破仑三世、俾斯麦、亚历山大二世、慈禧、明治天皇、梅特涅和林肯。八人均在原作 1.13.9 的 `common/character_templates/` 中有历史模板和有效 DNA 引用。维多利亚女王、亚历山大二世和梅特涅出现在 1836 年开局角色历史中；其余五人将由展柜专用场景按原作模板创建，不等待正常事件或年份条件。

此轮不制作角色板块网页、不改动原作文件、不为缺少 DNA 的角色猜测面部数据，也不承诺由游戏模组独立写出图像文件。

## 方案选择

原作支持的角色肖像控件已使用 `GetAnimatedPortrait`，并以 `politician_environment` 和 `camera_leader` 组合渲染人物。首轮复用这组原作环境与相机，使用同一待机动作，得到与角色面板一致的渲染质感。相比直接用历史肖像或生成插画，这能保留原作 DNA、服装、年龄和材质，并让资料库角色图保持统一。

实现由两个相互独立的部分组成。展柜模组负责创建一名当前待拍角色、把该角色放入固定肖像控件，并提供可预测的角色切换操作。截屏工具负责在固定窗口尺寸下执行切换、等待画面稳定、截取预设半身区域、写入图像文件和索引。游戏脚本中没有已确认的“导出肖像到文件”接口，因此截屏工具必须在 Windows 桌面层执行；模组不承担文件输出。

首轮固定为原作角色面板的半身构图。环境、相机、画面分辨率、窗口尺寸和裁切框记录在展柜清单中。截屏工具每次输出角色键、文件名、图像尺寸、生成时间、窗口尺寸、裁切框和文件哈希。截图失败、窗口尺寸不符、角色键不匹配或肖像仍为默认占位图时，该角色应记录失败原因且不写入正式索引。

## 文件边界

后续实施将在资料库中新增 `portrait-studio/`，保存展柜模组、角色清单和说明。模组目录只包含 Victoria 3 可加载的描述文件与脚本资源，不复制原作 DNA、网格或材质文件。`scripts/` 下的截屏工具与清单校验器只读取展柜清单和截屏目录；图片输出进入忽略目录，避免把大批量二进制图像混入源码提交。

正式索引为 UTF-8 JSON，条目以原作模板键为稳定标识。它将包含显示名、DNA 键、原始角色模板、图像相对路径、规格和哈希。未来角色板块只需读取该索引和静态图像，不能依赖游戏安装目录。

## 验证与完成条件

首轮完成需要同时满足以下条件：八个模板键和 DNA 键均通过静态校验；模组在原作 1.13.9 中能逐个显示八人；每张图使用相同的窗口规格和裁切框；索引中的八个哈希均与实际文件一致；人工核对每张图确认没有默认占位肖像、空白人物、错人、裁切掉头部或明显加载未完成。

技术验证分两步进行。首先在不启动游戏时检查清单、原作模板与 DNA 的对应关系，以及索引、文件尺寸和哈希。其次在游戏启动后依次截取八人，保留原始全窗口截图作为仅本地的诊断证据，再从中生成正式半身像。任何自动化未能稳定完成的步骤必须明确记录为手动操作，不能把未验证的脚本宣称为自动出图。
