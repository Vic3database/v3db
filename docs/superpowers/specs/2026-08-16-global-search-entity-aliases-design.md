# 全局搜索实体别名设计

## 目标

全局搜索应检索实体的基础名称、正式名称变体和内部兼容别名。名称变体必须来自游戏定义与本地化之间可以明确核实的归属关系，不通过字符串相似度或本地化键格式猜测归属。查询名称变体时仍只产生对应实体的一条结果，点击后进入原有详情页。

原版 1.13.10 当前可直接核实的数据包括 294 条动态国名、369 条动态地区名、145 个公司动态类型名，以及 19 条建筑脚本兼容别名声明。Victorian Century 使用相同的数据提取和站点构建流程，并保留模组覆盖与新增定义。

## 索引契约

每个 `VIC3_SEARCH_INDEX` 条目继续保留 `names` 作为基础显示名，并增加两个用途分离的字段：

```js
{
  kind: "country",
  key: "CHI",
  names: {
    "zh-Hans": "中国",
    en: "China"
  },
  aliases: {
    "zh-Hans": ["大清", "中华帝国", "中华人民共和国"],
    en: ["Dai Ching", "Empire of China", "People’s Republic of China"]
  },
  internalAliases: []
}
```

`aliases` 只保存玩家可见、具有正式本地化的名称变体，按语言分别保存，去重时保留游戏定义顺序并排除与基础名相同的值。`internalAliases` 保存游戏定义中的兼容 ID 或旧脚本键，不按语言拆分，不作为界面标题。字段为空时可以省略，以控制索引体积。

首批数据来源如下：

- 国家条目从国家的 `dynamicNameVariants` 读取动态国名。
- 地区条目从 `stateRegions[].dynamic_name_variants` 对应的站点字段读取动态地区名。
- 公司条目从 `companies[].dynamic_company_type_names` 读取正式类型名称。此类名称是“公司”“财团”等可见构成词，只与定义中明确引用它们的公司条目关联。
- 建筑条目从 `common/buildings` 定义的 `aliases` 读取脚本兼容 ID。提取器应把该字段写入 `buildings.json`，站点构建器再转入 `internalAliases`。

后续文化、商品、法律等实体出现可明确归属的正式变体或兼容 ID 时，沿用相同字段接入。通用模板、修正名称、描述文本和无法确定所属实体的本地化键不进入别名索引。

## 匹配、排序与显示

默认搜索的匹配集合由内部键、基础名称、正式别名、内部兼容别名、现有分组名称和国家关联共同组成。详细搜索的说明、选项、脚本等字段保持现有开关控制，不与别名字段混用。

结果排序采用以下优先级：当前语言基础名精确命中、当前语言正式别名精确命中、内部键精确命中、当前语言基础名前缀、当前语言正式别名前缀、其他语言基础名或正式别名、内部兼容别名、普通包含命中、详细字段命中。同一优先级继续按实体类型和当前语言标题排序。

基础名称命中时继续显示基础名称。正式别名命中时，标题显示当前语言中实际命中的正式别名；基础名称可作为较弱的副信息，但一个实体不得因多个别名生成多条结果。内部兼容别名命中时继续显示正式基础名称，避免把脚本键伪装成玩家可见名称。

例如查询“清”时，国家 `CHI` 以“大清”显示，国家 `CMI` 以“清迈”显示；两项都进入结果列表。查询 `building_barracks` 时只返回其对应建筑，并显示该建筑当前的正式名称。

## 数据流与兼容性

`extract_vic3_countries.mjs` 负责保留源定义中的结构化别名，`build_wiki.mjs` 负责把各实体的变体转成统一搜索字段，`content_search_index.mjs` 继续在生成日志、事件和决议条目时保留既有索引字段。前端只消费索引，不在浏览器中遍历完整国家、地区或公司数据来推导别名。

原版 1.13.10、`site/vc` 和独立 `Victorian Century Database` 使用相同前端匹配逻辑。现有旧版本站点在重新生成后获得对应版本自身的别名；本次实现至少重建当前原版 1.13.10 与两个 VC 输出。索引中缺失 `aliases` 或 `internalAliases` 的旧数据继续按原有名称匹配，不产生运行错误。

## 验证

静态检查应确认国家、地区、公司和建筑四类样本的字段来源、语言值、去重与归属关系，并确认内容索引合并过程不会删除新字段。浏览器检查应在原版和 VC 中验证“大清/清迈”的单字查询、动态地区名查询、公司类型变体查询、建筑兼容 ID 查询，以及点击结果后的详情路由。

回归检查还应确认基础名称查询仍显示基础名称，一个实体在同一查询中只出现一次，中文界面不会因英文别名命中而无条件拼接所有英文名，详细搜索开关的字段隔离保持不变。构建完成后检查三个当前站点的索引与前端文件一致性，并执行既有全局搜索、内容搜索、数据分块和独立 VC 站点检查。
