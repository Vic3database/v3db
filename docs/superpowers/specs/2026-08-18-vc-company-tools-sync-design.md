# Victorian Century 公司工具同步设计

## 目标与范围

现有公司产业组合求解器和公司建筑组合器从原版 1.13.10 扩展到 Victorian Century。主站源码继续作为唯一功能实现，独立 `Victorian Century Database/` 与发布副本 `site/vc/` 通过现有 VC 构建流程取得相同脚本、样式和页面结构。原版 1.13.9 仍不提供这两个入口，直接访问 `#/company/solver` 或 `#/company/composer` 时返回普通公司板块。

VC 两项功能使用当前资料库的全部数据，包括 231 家公司、模组新增或调整的公司定义、98 种名贵商品、固定建筑、互斥扩展建筑、文化和国家限制及繁荣效果。现有 VC 公司涉及的建筑集合与原版相同，均为求解器五类中的 48 项，因此沿用资源、农业、轻工业、重工业与军工业、基建及其他的分类、顺序与图标，不增加 VC 专用类别。

## 共用实现与数据流

`companySolverAvailable()` 和 `companyComposerAvailable()` 改为依据当前数据环境判断。原版主站仅在载入 1.13.10 时开放；设置了 `VICTORIAN_CENTURY_SITE_CONFIG` 且公司数据已经载入的独立 VC 站点同样开放。两个入口、子路由回退及板块状态继续复用现有 `boards.js`、`ui.js` 和运行时状态，不建立 VC 专用分支页面。

求解器把当前 `companies`、`prestigeGoods`、`goods` 和建筑记录传给现有 Worker 或异步备用核心。算法继续处理固定建筑与每家公司一个互斥扩展组，保留公司数量上限、自动递增、名贵商品条件、不使用统一建设联合体、不限制文化或国家、分页、公司使用率和详情展示规则。结果中的公司名称、图标、限制、繁荣效果与名贵商品从当前 VC 数据和本地化中取得，因此 VC 新增公司可以成为结果成员。

组合器继续从当前 `companies` 生成无分页图片墙，沿用公司类型、名贵商品、资料片和建筑筛选。选择 VC 公司后，现有组合核心合并固定建筑、所选互斥扩展、名贵商品、文化与国家限制及繁荣效果；同字段繁荣效果继续相加。VC 新增公司图标使用现有 WebP 或 PNG 回退机制。

`scripts/build_victorian_century_site.mjs` 继续复制 `site/app`、`site/styles`、本地化及主页面，并发布到 `site/vc`。构建生成的 VC 页面需要包含求解器核心、Worker、备用核心、组合器核心和两个界面脚本的版本化引用。Worker 使用相对路径导入核心模块，因此可以在 HTTP、独立文件页面的备用执行路径及 `site/vc` 中工作；文件协议下无法建立 Worker 时继续使用已有异步备用核心。

## 错误处理与兼容性

若当前资料库没有公司数据、核心脚本未载入或路由环境不受支持，入口保持隐藏，直接路由返回公司板块，不显示可执行的空页面。Worker 初始化或运行失败时继续切换到本地异步求解；两条路径都读取同一批 VC 公司数据并保持相同公司数量与名贵商品约束。VC 数据中的建筑键若将来超出现有分类，组合器仍在未分类区域显示，求解器只显示明确列入可选范围的建筑，避免自动把政府建筑、奇观、自给建筑或金矿场加入产业选择。

## 验证标准

静态检查确认两个功能在主站源码与两份 VC 输出中包含完整脚本和缓存标识，独立站不再被可用性判断排除。浏览器检查分别打开 `Victorian Century Database/index.html` 与 `site/vc/index.html`，验证普通公司页同时显示两个入口，求解器显示 48 个建筑并能产生 VC 数据结果，名贵商品筛选读取 VC 名贵商品，组合器显示 231 家公司并可选择至少一家 VC 新增公司。选择新增公司后，右栏必须显示其固定建筑、互斥扩展和 VC 名贵商品；桌面与窄屏均不得产生横向溢出。

原版回归继续覆盖 1.13.10 的求解器与组合器全部现有行为，以及 1.13.9 的入口隐藏和路由回退。核心、Worker、合同、VC 独立站和两套浏览器检查全部通过后，才能记录本地完成状态。本轮不包含提交功能实现、推送或公开部署，除非另有明确指示。
