# 史实角色关系与君主家族设计

## 目标与范围

第一阶段只整理当前角色库中的 1,983 个角色，以君主、继承人及其现有角色近亲为优先范围。正式关系包括父母与子女、配偶、兄弟姐妹、王朝成员、游戏开局继承和历史继位。父母与子女、历史继位具有方向；配偶与兄弟姐妹没有方向；王朝使用成员记录，不为同一王朝的每两个人生成关系。游戏开局继承表示开局统治者与游戏指定继承人的政治关系，历史继位表示某项君主头衔实际发生的前任与继任，两者不能合并。

关系两端都必须明确对应现有角色键。史料中出现、但未被当前角色库收录的人不增加辅助人物节点，也不能成为可点击关系。经过复核的单端资料可以形成缺失人数统计，用于说明尚有亲属未被角色库收录；姓名和身份只保留在复核资料中，不进入公开角色数据。第一阶段不扩展普通人物社交关系，不增加独立王朝板块，也不根据同姓、相近译名或同一王朝推断亲属关系。

## 采集、对应与复核

采集流程先补齐游戏角色身份。生成程序同时识别角色模板中的 `role = ruler`、`role = heir`、旧式 `ruler = yes`、`heir = yes`，以及开局历史文件中的统治者、继承人和国家归属。游戏注释中的亲属描述只作为候选线索，除非描述能够明确对应关系双方；无法消除身份歧义的注释不能进入正式数据。

外部候选以现有肖像资料中的 Wikidata 编号为起点，再使用角色键、英文姓名、中文姓名、别名、出生年份、国家、头衔和已确认亲属生成其他人物对应。姓名或别名一致是基本条件，出生年份、国家、头衔和亲属信息中至少一项还需提供辅助确认。同姓、同王朝或相近译名单独出现时不能确认人物身份。

关系候选从 Wikidata 的父母、子女、配偶、兄弟姐妹、所属王朝和君主头衔陈述取得。存在缺项或歧义时，使用 Wikipedia 人物页、人物传记或王室谱系资料复核。每条正式关系必须保留至少一项能够直接支持该关系的资料依据；只支持人物身份的资料不能代替关系依据。不同资料互相冲突时，各项陈述和定位信息一并保存，记录标为“冲突”，待人工复核后才能转为“已确认”。

候选状态分为“待复核”“已确认”“冲突”和“排除”。只有“已确认”记录参与正式数据生成。排除记录保存排除原因，防止后续批次重复提出同一错误候选。采集报告按批次统计已识别统治者和继承人数、已确认关系数、缺少外部身份编号人数、冲突数、排除数和只有单端角色的关系数。

## 数据结构与生成边界

人工复核资料与角色基础数据分开保存，角色数据重新生成时不得覆盖复核结论。候选记录保存候选编号、双方身份、关系类型、人物对应依据、关系依据、状态、复核说明和复核时间。正式关系从“已确认”候选生成，使用以下规范：

- 父母关系保存为“父母角色键 → 子女角色键”。页面从一条记录派生父亲或母亲、子女两个方向的显示。
- 配偶和兄弟姐妹按两个角色键的固定排序保存，每一对只保留一条记录。
- 王朝成员记录保存角色键、王朝键、王朝中英文名称、适用时间和资料依据。角色属于多个王朝或资料存在不同分类时，分别记录适用时间，冲突项不公开。
- 游戏开局继承保存统治者角色键、继承人角色键、国家键、开局日期和游戏文件位置。
- 历史继位保存前任角色键、继任角色键、政权或国家键、君主头衔键、头衔中英文名称、交接日期或时间范围和资料依据。同一人物拥有多个头衔时分别记录。

每项资料依据包含资料类型、页面或文件标题、网址或游戏文件路径、能够定位陈述的段落或字段，以及访问或提取日期。Wikidata 资料同时保存条目编号和属性编号。公开数据只包含页面渲染所需的已确认关系、王朝成员、继承信息、缺失人数汇总和精简后的资料依据；待复核、冲突、排除及未收录人物身份不会进入站点数据块。

角色关系作为独立数据块生成并登记到版本数据索引。普通角色列表仍只加载角色与肖像数据；打开角色详情时再加载关系数据块。关系数据块加载失败时，现有基本资料、肖像和特质继续显示，关系区域给出加载失败提示。当前角色没有已确认关系或缺失人数时，不显示关系区域。

## 角色详情界面

角色详情延续当前三栏页面和已有详情宽度，在基本资料、肖像与现有字段之后增加关系内容。呈现层级参考 [Wikipedia 的维多利亚女王人物页](https://en.wikipedia.org/wiki/Queen_Victoria)与[英国君主家族树](https://en.wikipedia.org/wiki/Family_tree_of_British_monarchs)，使用 Vicdata 现有颜色、间距、按钮和链接形式。

“人物关系概览”先以信息框形式列出王朝、父亲、母亲、配偶、子女和兄弟姐妹。已收录人物使用可点击名称，打开对应角色详情；经过复核但未被角色库收录的亲属只显示“另有若干人未收录”，不显示姓名或不可点击节点。点击王朝名称在当前详情中展开该王朝已确认成员列表，第一阶段不增加新路由。

“局部家族图”位于概览之后并默认折叠，只绘制当前角色上下各一代：父母、当前角色、配偶、兄弟姐妹和子女。页面不递归展开整个王朝。桌面端关系较多时允许组件内部横向滚动，不能扩大整页宽度；窄屏改为按父母、兄弟姐妹、配偶、子女排列的分组列表。点击图中人物进入对应角色详情。

“王位继承”独立于血亲图。每项历史头衔使用一个继承框，依次显示前任、当前人物及在位时间、继任；缺少任一现有角色时显示未收录说明，不创建节点。游戏开局继承在历史头衔框下另列国家、开局统治者和指定继承人。每个关系区提供折叠的“资料依据”，显示资料链接、游戏文件位置、适用国家或头衔、时间范围和复核状态。

## 校验、异常与验收

生成校验必须拒绝指向本人的父母、配偶、兄弟姐妹或继承关系，拒绝不存在的角色键，拒绝缺少国家或头衔的历史继位，拒绝缺少国家和开局日期的游戏开局继承。配偶与兄弟姐妹执行规范排序和去重；父母与继位检查同向重复及直接环；王朝成员按角色、王朝和时间范围去重。只有单端角色、人物对应不确定、关系依据不足或资料冲突的记录停留在复核资料中。

数据测试覆盖新旧角色语法、开局历史归属、人物对应条件、四种复核状态、五类人物关系、王朝成员、两种继承口径、资料依据字段、缺失人数汇总、角色键完整性和重复关系。代表性样例至少包含有父母和子女的君主、拥有配偶与兄弟姐妹的角色、同属一个王朝的多名角色、拥有多个君主头衔的人物、游戏开局继承与历史继位不同的情形，以及关系一端未收录的情形。

前端契约和浏览器测试覆盖关系数据按需加载、无关系时隐藏区域、概览导航、王朝成员展开、家族图折叠、多个继承框、资料依据折叠、中英文文字和数据加载失败。桌面端检查详情区宽度、长姓名、组件内部横向滚动和整页无横向溢出；窄屏检查分组顺序、点击导航及折叠状态。现有角色筛选、每页一百人的分页、肖像、特质翻译和详情字段必须通过回归检查。

第一轮以君主和继承人为中心，依次纳入其在现有角色库中的父母、子女、配偶、兄弟姐妹和王朝成员。每一批完成后生成统计并运行数据校验；未完成的候选不影响已经确认的家族显示。君主家族达到可检查的覆盖度并完成前端验收后，再单独设计普通史实人物关系的扩展范围。
