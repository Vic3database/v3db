# Vicdata 公司产业组合求解器设计

## 范围与页面

本功能只面向原版 Victoria 3 1.13.10。它是公司板块的子板块，不继承公司列表已启用的资料片、公司类型、地区或其他筛选条件；每次计算均以 1.13.10 的全部 221 家公司为候选。公司板块左栏增加“产业组合求解器”入口，入口打开 `#/company/solver`。普通公司列表、普通公司详情以及 Victorian Century 页面不改动。

求解器主区域顶部显示建筑图标目录。目录沿用现有公司左栏的排序和中文名称，分为矿业五项、其他资源五项、农业十六项、轻工业七项、重工业七项、军工业三项、基建及其他五项，共四十八项。矿业依次为煤矿、铁矿、铅矿、硫矿和金矿；其他资源依次为渔业码头、捕鲸站、伐木营地、橡胶种植园和油井。金矿区、奇观、政府建筑和其他未列入公司产业筛选的建筑不进入目录。图标直接使用已有建筑图标。每个图标是一个开关，用户可以任意多选；图标行末放置“执行求解”按钮。空选时不启动计算，任何目标改变都会使已有结果失效，必须重新执行。

执行后，主区域显示精确方案总数、当前页码、前后页控件和每页二十个方案卡片。页面不一次创建全部方案卡片。卡片的右上角只有右箭头，点击后在现有右栏打开该方案的组合详情。结果卡片本身没有公司、建筑或名贵商品跳转链接。组合详情为方案中的每家公司提供详情卡片，包含建筑、当前产业选择、成立条件、繁荣效果、名贵商品、文化与国家限制；其中公司、建筑和名贵商品保留指向现有详情页的链接。

## 方案表达与详情

一张结果卡片代表一个完整的公司组合，不按公司拆成多张卡片。桌面端标题显示“方案 N”和右箭头。第一行左侧连续排列组合内的公司图标，右侧连续排列这些公司的名贵商品。第二行按“选中建筑 + 额外建筑（可选建筑）”显示所有公司的合并覆盖关系。选中建筑是当前目标中由该方案覆盖的建筑；额外建筑是所选公司固定覆盖、但没有被选为目标的建筑；可选建筑是各公司未选中的互斥扩展建筑，放在括号内，不计为当前方案的同时覆盖或额外覆盖。没有内容的部分不显示。第三行只在组合含有国家或文化限制时显示这些限制。限制由公司成立条件脚本中已提取的国家和文化引用生成；组合详情仍显示原始成立条件，避免把包含同盟、附属国或其他条件的引用简化为无条件锁定。

例如目标为橡胶种植园、油井和工艺装备工坊，方案由孟买缅甸贸易公司和通用工具公司组成时，第一行显示两家公司的图标以及“缅甸柚木”“精密工具”。第二行显示“橡胶种植园、油井、工艺装备工坊 + 伐木营地（炼钢厂）”。括号中的炼钢厂是未选择的扩展建筑，不能与当前已选择的扩展建筑同时算作覆盖。此组合没有文化或国家限制时，第三行不显示。

窄屏卡片保留方案标题与右箭头，并将内容依次分为公司图标、名贵商品、选中建筑、额外建筑、可选建筑和硬性限制六行。缺少内容的行不渲染。组合详情右栏显示方案编号、公司数量、目标覆盖、额外覆盖数量以及组合内每家公司的详细卡片。详细卡片使用现有公司详情中的建筑、成立条件、繁荣效果和名贵商品数据，但在建筑一栏明确标出固定建筑、当前选定的扩展建筑与未选的可替代扩展建筑。

## 数据、求解与验证

求解器使用独立的纯数据与算法模块，页面渲染不直接实现搜索。每家公司预处理为固定建筑集合、扩展建筑选择组、名贵商品、繁荣效果、文化与国家限制以及现有详情所需字段。四十八个可选建筑用 `BigInt` 位掩码表示。`building_types` 全部进入固定集合；`extension_building_types` 是一个“可不选、最多选择一项”的互斥组。产业到公司候选列表在预处理时建立倒排索引。

若被选公司扩展组中恰有一个目标建筑，该建筑就是该公司在本方案中的确定扩展选择，不能替换为同组的非目标建筑。若一个扩展组中有多个目标建筑，搜索为每一个可能的确定选择建立分支；同一家公司只能选择其中一个，其余目标必须由其他公司覆盖。扩展组没有目标建筑时不占用选择位，全部保留为卡片中的可选建筑。方案唯一键由排序后的公司键和每家公司实际确定的扩展建筑组成。固定建筑和实际确定的扩展建筑共同参与目标覆盖；只有固定建筑的非目标部分计入额外覆盖。删除组合中的任意一家公司后仍能覆盖全部目标的组合不是极小满足集合，必须丢弃。

搜索运行在 Web Worker 中，主线程只处理目标选择、进度和当前页绘制。Worker 先移除与目标完全无关的公司，再以当前未覆盖目标中候选公司最少的建筑作为分支点。分支按新增目标覆盖数排序，并在剩余候选公司的并集不能满足缺口时停止。Worker 枚举全部极小满足方案，得到精确总数；紧凑结果保持在 Worker 内，主线程按页请求二十项。排序固定为公司数量升序、额外固定覆盖建筑数量降序、公司名称稳定排序。执行新查询时必须取消旧 Worker 任务，防止过期结果写入界面。

测试应覆盖固定建筑覆盖、单个目标扩展建筑、同组多个目标扩展建筑、不可覆盖目标、极小满足集合去除、唯一键、排序、二十项分页和限制聚合。静态合同检查应验证 48 项建筑目录及顺序、金矿存在而金矿区不存在、`#/company/solver` 路由、卡片无直接详情链接、右箭头与组合详情链接、中文与英文界面文本。浏览器检查应验证桌面和窄屏的卡片行序、一次只渲染二十项、右箭头打开右栏组合详情、详情卡片中的公司和建筑链接以及重新选择目标后旧结果失效。
