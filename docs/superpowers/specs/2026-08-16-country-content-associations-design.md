# 风味日志、事件、决议与国家关联设计

## 目标与范围

为 Victorian Century 合并内容中的风味日志、事件和决议生成可核验的主体国家范围，并在国家详情与内容详情之间建立双向跳转。主体国家指能够拥有、开启或触发该内容的国家。脚本中仅作为目标、对手、受影响对象或背景出现的国家不计入主体范围。

本次范围包含 `database/victorian_century` 中合并后的日志、事件和决议、VC 独立站、主站使用的 VC 发布副本，以及三个内容板块和国家详情。通用内容没有可靠国家范围时不建立关联。不会依据标题、描述文本、文化、地域、法律或文件名推测国家。

## 数据结构

日志、事件和决议统一增加以下字段：

```json
{
  "country_scope": ["AUS"],
  "country_scope_evidence": [
    {
      "country": "AUS",
      "kind": "direct",
      "source_field": "is_shown",
      "expression": "c:AUS ?= ROOT"
    }
  ]
}
```

`country_scope` 是去重并按国家标签排序的主体国家标签。`country_scope_evidence` 保存每个国家的判定依据；证据种类为 `direct`、`group`、`inherited` 或 `override`。直接证据记录所在脚本字段和匹配表达式；组证据记录命名空间、日志组或来源文件及其覆盖率；继承证据记录上一项内容、关系类型、调用作用域和传播起点；人工校正记录理由与脚本位置。

三类内容统一增加 `content_kind`，值为 `flavor` 或 `generic`。最终 `country_scope` 非空时为 `flavor`，为空时为 `generic`。事件现有的 `event_kind` 与 `content_kind` 保持相同结果，兼容已有筛选和界面逻辑；日志与决议使用 `content_kind` 供后续筛选、统计和审计使用。

站点内容数据增加按国家反向索引：

```json
{
  "contentByCountry": {
    "AUS": {
      "journals": ["je_matter_of_hungary"],
      "events": ["hungary_events.1"],
      "decisions": ["aus_integrate_crown_lands_decision"]
    }
  }
}
```

反向索引只保存 ID，标题、分组、来源和 VC 变更标签仍从原内容记录读取，避免生成重复信息。正向范围与反向索引必须通过一致性检查。

## 主体国家判定

直接证据只读取决定当前内容能否由某国拥有、开启或触发的字段。日志读取未激活时显示条件、开启条件及等价主体限制；决议读取显示条件和执行条件；事件读取触发条件以及明确约束事件接收国的等价条件。`c:AUS ?= ROOT`、`ROOT ?= c:AUS`、`c:AUS ?= this` 等表达式可产生奥地利主体范围。

完整原始脚本仍用于识别内容之间的调用关系，但不会把其中出现的所有 `c:TAG` 当作主体国家。位于效果、选项、完成效果或外交操作中的目标国家不会形成直接范围。

事件命名空间、日志组和决议来源文件可以提供稳定组范围。组内至少八成已有直接主体证据的内容必须指向不超过八个国家，才允许没有直接证据的同组内容继承该组范围。组名或文件名只用于标识统计范围，本身不构成证据。直接证据与组证据冲突时保留直接证据，并在审计报告中记录冲突。

现有事件分类中已经确认的国家专属命名空间校正继续保留，并转换为可审计的组证据或人工校正证据。原版 1.13.10 事件数据中的 `country_scope` 作为回归基线，VC 合并后重新计算，不能直接覆盖 VC 调整后的脚本。

## 关系继承

构建程序从以下明确调用建立有方向的关系：日志、事件或决议直接触发事件，以及日志、事件或决议直接增加、激活或创建日志。只有能确定调用所处国家作用域时才传播范围。

调用发生在当前主体国家作用域时，目标内容继承来源内容的主体国家。调用位于 `c:HUN` 等明确国家作用域时，目标内容关联该指定国家。调用位于随机国家、任意国家、临时变量国家或无法解析的嵌套作用域时不传播。脚本仅检查 `has_journal_entry`、仅提到事件 ID，或把另一内容作为条件时不形成传播关系。

继承计算反复运行到国家范围不再变化。每条继承证据保存直接上一项内容和最初的可靠证据起点，防止多级事件链失去来源。多条可靠路径指向不同主体国家时保留全部国家。循环调用不会无限扩张；已访问的“内容 ID—国家—起点”组合只处理一次。

## 人工校正与审计

无法从脚本结构准确识别、但有明确源码依据的历史事件链放入独立人工校正表。每项校正必须包含内容类型、内容 ID、国家标签、增加或排除操作、理由、来源文件和行号。校正表不接受仅依据标题、历史常识或描述文本得出的关联。增加校正在关系传播前作为可靠起点应用，使其能够沿明确调用继续传播；排除校正在传播结束后应用，并清除由被排除证据作为唯一起点产生的继承范围。

构建时生成审计摘要，至少包含三类内容的总数、具有国家范围的数量、各证据类型数量、无法解析的国家标签、组证据冲突、无效关系目标和人工校正数量。无法在国家数据库中解析的标签保留在审计报告中，不写入站点反向索引，也不生成不可点击的国家条目。

## 界面与交互

国家详情在基础信息之后增加“风味内容”区域。区域顶部显示日志、事件和决议数量，三类内容使用独立可展开分区并默认收起。展开后按可读分组名称、内容 ID 排序；每项显示标题、ID、所属组及已有的“VC 新增”或“VC 调整”标签。点击条目切换到对应板块并直接打开该项详情。

日志、事件和决议详情的标题下方增加“相关国家”。每个国家条目显示国旗、中文名称和标签，并可进入对应国家详情。事件详情现有的纯文本国家范围改用这一共用组件。没有可靠国家范围时不渲染该区域。

国家详情沿用右栏滚动条，“风味内容”分区不设置内部滚动条。窄屏下三个分区按日志、事件、决议顺序纵向排列。直接打开 `#/country/TAG`、`#/journal/ID`、`#/event/ID` 或 `#/decision/ID` 时，关联区域与站内跳转后的结果一致。

## 组件边界

国家范围解析器只负责从单条内容提取直接证据和有作用域的调用关系。组分类器只负责根据直接证据统计稳定范围。传播器只根据已经解析的关系传递国家范围。反向索引生成器只从最终 `country_scope` 建立国家到内容的映射。人工增加校正在传播前加入可靠起点，人工排除校正在传播后清理对应证据链，随后统一计算 `content_kind` 并生成反向索引。

前端使用一个共用的相关国家组件和一个国家风味内容组件。内容板块负责传入当前记录，国家详情负责传入国家标签；组件不在浏览器中重新分析脚本。数据分析规则的变化不会要求修改界面组件。

## 验证标准

数据测试覆盖主体条件的正反方向写法、目标国家排除、当前主体作用域传播、明确国家作用域传播、未知作用域不传播、多级继承、多国合并、循环终止、组覆盖率阈值、人工校正和正反索引一致性。

回归测试核对原版 1.13.10 已确认的 836 条风味事件国家范围；VC 调整条目使用合并后的脚本重新判定。抽样核对奥地利、英国、俄罗斯、美国、日本、印度相关政权等内容较多的国家，并检查至少一个仅作为对手出现的国家不会被关联。

浏览器测试覆盖国家详情展开三类内容、国家到日志／事件／决议的跳转、三类内容返回国家详情的跳转、国旗与名称显示、VC 变更标签、默认收起状态、右栏单一滚动条和窄屏纵向布局。通用内容不得出现在国家风味内容区域，没有关联的内容详情不得显示空白“相关国家”区域。

构建完成后同步验证主站源文件、`Victorian Century Database` 与 `site/vc` 发布副本。此次实现不包含提交、推送或公开部署内容数据与前端改动，后续按项目发布流程单独处理。
